# Astra AI Play・二視点動画検証

検証日：2026-10-19。同一PCでStage1→Stage2→Stage3を各1回実施し、**3/3完走・衝突0・転倒0**。各Stageの映像検証後に次Stageへ進めた。これは新規上位判断の動作確認であり、多数試行の成功率推定や実験11の固定経路再現試験ではない。

## 実行したモデルと観測

`collaboration.spawn_agent`で`gpt-6-astra`を明示指定した専用プレイヤーを起動し、共通プロンプト・ルール・APIを読ませた。バックエンドの細かなモデルrevisionは独立検証していない。指定名と未確認事項は各sessionの`astra/model-dispatch.json`および指令の`model_identity`に記録した。

プレイヤーには過去の固定経路を読ませず、一人称のraw画像と標準地図・真値姿勢を含む合成画像を実際に開かせた。標準courseの数値座標も利用した。したがって画像のみの認識実験ではない。経路は判断JSONを保存してから送信し、固定再現APIは呼んでいない。下位追従器は大域経路探索を行わない。

## 動画方式と品質

従来の5fps画像サンプリングから、ゲームが標準保存した50HzのFULLPHYSICS状態を30Hzの表示時刻へ補間する方式へ変更した。1280×720、H.264、yuv420p、faststartのMP4を二視点で出力する。物理step、追加推論、学習は行わない。単純なフレーム複製によるfps変更でもない。

一人称は既存の頭部カメラ式、yaw0/pitch-16。三人称は既存の後方追従カメラを外部レンダラーで使用し、距離4m・注視高さ0.85m・俯角12度を固定、位置時定数0.30秒・ヨー時定数0.45秒で追従させた。フィルターの時間源を出力sim時刻に固定し、二視点の内部状態を分離した。壁・障害物は既存alpha0.25を使う。ゲームソース・モデルの編集は不要だった。

Stage1は全編120.433秒と走行抜粋22.767秒を保存。Stage2/3は走行約1秒前から終了までの抜粋を直接描画する`--action-only`を使用し、全時間の原状態・観測・消費量は保持した。二視点は同じ出力時刻・補間状態を使用する。各フレームのPTS、sim時刻、元状態行、補間率、SHA256、近傍の観測IDを対応表に保存する。再描画動画をAstraの実閲覧証拠と混同しない。

動画検証の最終数値は下記成果物の`analysis/ai-play-results.md`および各`video/*/validation.json`を参照。Stage1走行抜粋は各683フレーム、Stage2は各1,114フレーム（37.133秒）、Stage3は各1,236フレーム（41.2秒）。走行映像6本すべてで全デコード、30fps時刻格子、元画像・復号全画素・縮小画像の実更新30Hz、連続重複0、欠落0を確認した。PTS間隔誤差は浮動小数点丸めの範囲内。各動画の元状態間隔も最大約20msで欠落なし。

Stage1全編の圧縮前画像は重複0だが、長い静止中の微細な変化が非可逆圧縮で消え、復号全画素の連続重複は一人称211・三人称70、実更新は28.248Hz・29.419Hzだった。160×90へ縮小すると重複421・649、更新26.503Hz・24.610Hzになる。これらを隠して全編すべてが実更新30Hzとは主張しない。走行抜粋では両視点とも圧縮・縮小後も重複0だった。

Stage2の三人称サンプルでは旋回中も全身が画面内にあり、障害物を透過して視認できる。1フレームの最大ヨー変化はロボット2.348度からカメラ1.507度、XY加速度RMSは0.839から0.262m/s²へ低減した。完全に瞬間的な真後ろへ一致するのではなく、旋回に遅れを持って追従する。ブラウザごとの実時間再生・人による連続視聴評価は未検証で、全MP4ソフトウェア復号とフレーム検証、サンプル目視の結果である。

Stage3でも両視点のサンプルを目視確認し、後方カメラで全身を視認できた。最大ヨー変化は1.327→0.798度/フレーム、XY加速度RMSは0.924→0.228m/s²。カメラの揺れ低減と描画更新の増加を数値で確認した。

## 実装と検証

- `media/timeline.py`：状態時刻の検証、30Hzサンプリング、MuJoCo姿勢補間、sim時刻カメラ。
- `media/render.py`：ゲーム読取専用の二視点描画、H.264出力、状態対応表、原入力ハッシュ照合。
- `media/validate.py`：全復号・整数PTS/time_base・解像度・重複・欠落検証。表示用の丸められたpts_timeを使うと100秒以降で誤判定する問題を修正した。
- `media/clip.py`：原動画と対応を残す走行抜粋。`analysis/ai_play.py`：待機込みの原結果と参考値を分けた集計。
- CLI `video`、`--action-only`、API応答の`--brief`、ソース用`tools/aiplay`を追加。共通プロンプトの内容は今回の実験中に変更していない。
- 単体20件成功、別途localhost HTTP統合1件成功。姿勢補間、時刻異常拒否、30fps格子、カメラ時間源、API不正入力・停止・shutdownを確認。

navigation.pyは実験11と同じSHA256 `f07499a1d0eced5f0d4baac6a9a7fd13c4778247a15b069fd8677a93f1c37d55`。通常追従の数式・定数を変更していない。既存安全テストも成功した。実験11全9,757ファイルを照合して追加0・削除0・変更0。ゲームとvendorの追跡ファイルも実行前後で同一だった。

ゲーム・動画環境は既存Linux/EGL、Python3.10.12、MuJoCo3.15.0、NumPy2.2.6、Torch2.14.1+cpu、Pillow12.3.0、既存FFmpeg7.0.2-static/libx264。Stage1の制御はゲームvenv、Stage2/3の制御は`/usr/bin/python3`を使用した。後者のdistribution一覧には複数版が含まれるが、実importのPillowは12.3.0と確認した。環境のインストール・更新はしていない。詳細はsessionのmanifest/environment-game/launchと`controller-import-environment.json`を参照。FFmpegバイナリはパッケージへ同梱しない。

## 残課題と公開状態

各Stage1回の確認であり、別PCや異なる描画性能での成功、画像のみの認識、実験11を上回る省エネルギー、上位の頻繁な再計画は検証していない。今回経路交換は実施していない。通信・APIの既存安全テストと実際の経路再判断を区別する。

操作承認待ちと上位判断待ちの影響が大きい。未承認操作を迂回せず、将来は利用者が許可範囲を事前に設定した環境で遅延を再評価する必要がある。ゲームを途中停止して待機Whを消す変更はしていない。動画は実時間キャプチャではなくsim時間の表示用補間であり、描画負荷・端末での再生速度・主観的な滑らかさには追加確認が必要。
