# 二視点の30fps記録

Astra向け観測候補は従来どおり一人称JPEGと標準地図・真値姿勢を約5fpsで取得・保存する。Astraが実際に開く画像はその一部であり、実閲覧IDは判断ログで別に記録する。下位追従は約20Hz。動画は試行終了後、ゲームが標準保存した約50HzのFULLPHYSICS状態から再描画する。リアルタイムの制御中には録画レンダラーを実行しない。

過去の実験11動画は1600×1000・5fpsの観測画像を直前値でサンプリングしていた。その画像を6枚ずつ複製しても動きの更新は5Hzのままである。新方式は元状態の並進・関節座標を30Hzの時刻へ補間する。自由関節のクォータニオンにはMuJoCoのdifferentiatePos/integratePosを使い、姿勢の球面上で補間する。新しい物理シミュレーションや政策推論は行わない。

## 実行

ゲームと依存が準備済みのPythonを使用し、既存FFmpegの絶対パスを渡す。ライブラリ・FFmpegの自動インストールは行わない。FFmpegバイナリは同梱しない。

```bash
MUJOCO_GL=egl PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src \
  /path/to/game/.venv/bin/python -m ecowalk_drive_aiplay.cli video \
  --session /path/to/session --trial ai_s1_01 \
  --game-root /path/to/game --ffmpeg /path/to/ffmpeg
```

session/video/試行名を新規作成し、既存出力は上書きしない。元ゲームのコミット・追跡ファイルハッシュが試行時manifestと一致することを検査する。状態時刻の逆行・重複、41msを超える欠落を拒否する。保存元ファイルと外部ゲームのハッシュを前後照合する。

`--action-only` を加えると、最初の移動指令の約1秒前から終了までだけを描画する。原状態・消費量・観測記録はすべて残り、manifestに元と描画区間のsim時刻を明記する。長い静止待ちの再描画を省くための任意の抜粋である。動画PTSは抜粋先頭を0とし、対応表には元のsim時刻を保持する。

- `first.mp4` / `third.mp4`：1280×720、30fps、H.264、yuv420p、faststart。既定では全試行のsim時間映像。`--action-only`指定時は走行区間の抜粋。
- 各 `*.frame_map.jsonl`：動画frame/PTS、sim時刻、元状態行2つ、補間係数、状態・RGBのSHA256、近い観測ID。
- `render-manifest.json`：元状態・結果のハッシュ、FFmpeg情報、カメラ設定、補間方法、入力不変検査。
- 各 `*.validation.json` / `*.decode.log`：MP4を最後までデコードした検証結果とshowinfoログ。
- `*.contact-sheet.jpg` とサンプルJPEG：一部フレームの目視確認用。

任意で待機を除いた走行抜粋を生成できる。全編は維持し、最初の非中立指令の約1秒前からフレーム単位で切り出す。

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src /path/to/game/.venv/bin/python \
  -m ecowalk_drive_aiplay.media.clip \
  --video-directory /path/to/session/video/ai_s1_01 --ffmpeg /path/to/ffmpeg
```

`first-action.mp4` / `third-action.mp4` と元動画frameへの対応を保存する。停止待ちや判断待ちを消費量集計から除外する操作ではない。

## カメラ

一人称はゲーム既存の頭部位置・姿勢式を使用。今回の攻略ではyaw0/pitch-16を維持し、Astraの実観測と同じ視点条件で再描画する。ただし再描画フレームをAstraが見た画像とは呼ばない。実際に見たJPEGとimage_idはobservationsとastraの記録を正とする。

三人称はゲーム既存の後方追従カメラを外部レンダラー内で使用。lookat高さ0.85m、距離4m、俯角12度で固定し、位置時定数0.30秒、ヨー時定数0.45秒で平滑化。描画処理のwall時間を使うとPC速度でカメラの動きが変わるため、出力フレームのsim時刻をフィルターへ明示的に渡す。一人称のresetで三人称フィルターが初期化されないよう二視点の状態を分ける。

壁・障害物はゲーム既存のalpha0.25を維持。モデル・形状・物性・採点は変更しない。旋回中は平滑化のため方向に遅れが生じる。常に瞬間的な真後ろと完全一致するとは主張しない。

## 品質判定と限界

全デコード、H.264、1280×720、フレーム数、PTSの単調性・30fps格子・始点、黒画面、元状態の欠落を検査する。PTSは丸められた表示用小数ではなく整数PTSとtime_baseから計算する。元RGBの全画素SHA256、MP4復号後の縮小前全画素チェックサム、160×90 RGBのSHA256を区別して連続重複と更新率を測定する。静止中の微小な変化は非可逆圧縮・縮小で消える場合があるため、全編と走行抜粋の両方を報告する。フレーム数だけを見て「滑らかになった」とは判断しない。

再描画はsim時間であり、PC上の実時間録画ではない。初期化前や完走後に状態保存のない時間は含まない。状態間補間は表示用であり、その中間の画像が実際に観測された証拠ではない。カメラを途中変更した場合、観測記録が5Hzなので切替時刻には最大約1観測周期の不確かさがある。元状態に欠落があれば、補間を延長して埋めずエラーにする。

H.264のソフトウェア全デコードは確認するが、あらゆるブラウザ・端末での再生を保証しない。観測用の合成地図はAstra向けJPEGに残し、動画は視認性を優先した1280×720のゲーム映像とする。
